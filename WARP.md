## Project Overview

AutoSpend is a Flutter-based personal finance tracker that automatically captures transaction data from SMS messages (primarily banking notifications) and provides expense tracking, categorization, and analytics. The app runs on Android and uses local SQLite database for data persistence.

## Architecture

### State Management: Riverpod
The app uses **Flutter Riverpod** for state management with code generation (`riverpod_annotation`).
- Providers are defined using `@riverpod` annotation
- Main providers in `lib/src/features/dashboard/data/dashboard_providers.dart`
- Repository layer uses providers for dependency injection

### Database: Drift (SQLite)
The app uses **Drift** (formerly Moor) for type-safe SQLite database access.
- Schema defined in `lib/src/core/database/database.dart`
- Database version: 2 (includes lending tracker fields)
- Main table: `Transactions` with fields:
  - Core: id, smsId, amount, merchant, category, type, timestamp, isManual
  - Lending: isLending, lendingType, linkedLendingId
- Important: The database implements duplicate detection with a ±5 minute time window to handle SMS delivery delays

### Feature Structure
The codebase follows a feature-first architecture:
```
lib/src/features/
  ├── categories/       # Category definitions and service
  ├── dashboard/        # Home screen, analytics, menu
  ├── onboarding/       # First-time setup flow
  └── transactions/     # Transaction management and UI
```

Each feature typically contains:
- `data/` - Repositories, providers, data models
- `presentation/` - UI screens and widgets

### Core Services
Located in `lib/src/services/`:

#### SMS Parser Service (`sms/sms_parser_service.dart`)
- Parses banking SMS messages to extract transaction data
- Supports multiple bank formats (Karnataka Bank, SBI, UPI notifications)
- Handles multiple amount and merchant name patterns
- Uses isolates for heavy parsing work
- Implements category inference from merchant names
- Key methods:
  - `parseSms()` - Parse individual SMS
  - `inferCategory()` - Auto-categorize from merchant name
  - `scanMessages()` - Batch process historical messages

#### SMS Service (`sms_service.dart`)
- Listens for real-time incoming SMS via MethodChannel
- Implements three-layer duplicate detection:
  1. In-memory cache (fingerprint: amount_type_timestamp)
  2. Exact smsId check
  3. Fuzzy duplicate check (±5 min window)
- Integrates with native Android SMS receiver via platform channels

#### Notification Service (`notification_service.dart`)
- Handles Android notification access for transaction capture
- Works alongside SMS service for redundancy

### Platform Integration (Android)
The app uses **MethodChannels** for native Android integration:
- `com.example.autospend/sms` - Real-time SMS listening
- `com.example.autospend/quick_actions` - Quick add functionality

Key native features:
- SMS broadcast receiver for transaction detection
- Notification listener service
- Quick action tiles for fast transaction entry

### Data Flow
1. **SMS Reception** → SmsService (via MethodChannel) → SmsParserService → Database
2. **Manual Entry** → AddTransactionSheet → TransactionRepository → Database
3. **Database Changes** → Drift Streams → Riverpod Providers → UI Updates

### Transaction Processing Pipeline
1. SMS received by Android BroadcastReceiver
2. Sent to Flutter via MethodChannel
3. SmsParserService validates and parses message
4. Duplicate detection checks run (3-layer)
5. Transaction inserted into SQLite database
6. Drift stream emits update
7. Riverpod providers rebuild
8. UI automatically updates

### Category System
Categories are predefined in `lib/src/features/categories/data/categories.dart`:
- 20+ categories with emojis and colors
- Includes: Food, Transport, Shopping, Bills, Rent, etc.
- Income categories: Salary, Business, Freelance, Investments

The app implements a "Time Travel" feature for date range filtering:
- Date ranges stored in SharedPreferences
- Keys: `filter_start_date`, `filter_end_date`
- Default filter: `customRange` (uses saved dates)
- Filters apply to:
  - Dashboard balance calculations

  - Analytics/spending charts
  - Quick categorize sheet

### Lending Tracker
Special transaction type for tracking money lent to others:
- `LendingType` enum: none, lent, returned
- Lending transactions excluded from net savings calculations
- Can link returned amounts to original lending transactions via `linkedLendingId`

## Important Technical Details

### Duplicate Prevention
The duplicate detection system is critical for data integrity:
- SMS can arrive delayed (network issues, poor signal)
- Same transaction may come from multiple sources (SMS + notification)
- Time window: ±5 minutes for fuzzy matching
- Fingerprint format: `${amount}_${type}_${timestamp_in_minutes}`

### Stream-Based Reactivity
All UI updates are driven by database streams:
- `watchAllTransactions()` - All transactions, sorted by timestamp
- `watchBalance()` - Real-time balance calculation
- `watchLendingSummary()` - Lending totals
- Never manually refresh UI - streams handle it automatically

### Provider Invalidation
When app resumes from background, providers are invalidated in `app.dart`:
```dart

ref.invalidate(filteredTransactionListProvider);
ref.invalidate(filteredBalanceProvider);
ref.invalidate(lendingSummaryProvider);
```

## Development Notes

### Adding New Transaction Categories
1. Add to `defaultCategories` list in `categories.dart`
2. No database migration needed (categories stored as strings)
3. Update category inference logic in `sms_parser_service.dart` if needed

### Adding New Bank SMS Formats
1. Add merchant pattern to `_merchantPatterns` in `sms_parser_service.dart`
2. Add amount pattern to `_amountPatterns` if new format found
3. Test with actual SMS samples
4. Consider sender ID format (`_senderIdRegex`)

### Database Schema Changes
1. Modify table definition in `database.dart`
2. Increment `schemaVersion`
3. Add migration logic in `onUpgrade()`
4. Run `dart run build_runner build`
5. Test migration with existing data

### Adding New Providers
1. Create provider with `@riverpod` annotation
2. Add `part '*.g.dart'` directive
3. Run code generator
4. Use `ref.watch()` in widgets to access data

### Working with Streams
- Use `StreamProvider` for database streams
- Use `AsyncValue` for handling loading/error states
- Access in widgets via `ref.watch(provider)`
- Streams automatically dispose when not watched

## Common Issues & Fixes

### Notification Listener Issues
**Problem:** Wrong merchant name or transaction type
- **Root cause:** Notification text parsing logic or merchant extraction patterns
- **Where to fix:** 
  - Merchant extraction: `android/app/src/main/kotlin/.../NotificationListener.kt` (`extractMerchantName()`)
  - Transaction type: `lib/src/services/notification_service.dart` (`_parseNotification()`)
- **Pattern priorities:**
  - Income: "paid you", "sent you", "received", "credited", "payment from"
  - Expense: "you paid", "you sent", "paid to", "sent to", "debited"
  - Income patterns MUST be checked before expense (more specific)

### Method Channel Mismatches
**Problem:** Flutter calls not reaching Android native code
- **Root cause:** Channel name mismatch between Flutter and Kotlin
- **Solution:** Verify channel names match exactly (singular vs plural, typos)
- **Example:** `com.example.autospend/notification` vs `com.example.autospend/notifications`

### Duplicate Transactions
**Problem:** Same transaction appearing multiple times
- **Root cause:** Transaction coming from multiple sources (SMS + notification)
- **Solution:** 3-layer duplicate detection:
  1. **Cache check** (exact smsId/notifId) - Prevents double processing
  2. **Database exact smsId check** - Prevents double insertion
  3. **Fuzzy duplicate check** - Catches SMS+notification for same transaction
     - Matches: amount + type + merchant + timestamp (±5 min)
     - ✅ Merchant matching prevents false positives (e.g., two ₹1 payments from different people)
- **CRITICAL:** 
  - Cache uses exact IDs (not fingerprints) to avoid blocking legit transactions within same minute
  - Fuzzy check includes merchant to avoid blocking different transactions with same amount

### Transaction Not Captured
**Problem:** Legitimate transaction not appearing in app
- **Root causes:**
  1. Duplicate detection too aggressive ❗ FIXED (multiple fixes applied)
     - Was blocking by minute-rounded fingerprint → Now uses exact IDs
     - Was ignoring merchant name → Now includes merchant in fuzzy check
  2. Notification listener not triggered (need app rebuild after Kotlin changes)
  3. SMS/notification not matching parsing patterns
- **Solutions:**
  1. Use exact ID-based caching instead of time-rounded fingerprints ✅ DONE
  2. Include merchant in fuzzy duplicate detection ✅ DONE
  3. Rebuild app: `flutter clean && flutter run`
  4. Check logs for parsing failures
  5. Add new patterns to merchant/amount extraction

### Wrong Transaction Icon
**Problem:** SMS showing manual icon instead of SMS icon
- **Root cause:** Historical SMS scan not prefixing smsId with `sms_`
- **Solution:** Ensure smsId format: `sms_` (SMS), `notif_` (notification), `manual_` (manual)
- **Detection logic:** `transaction_tile.dart` checks smsId prefix
